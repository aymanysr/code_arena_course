First, make a prediction

An older getActive() response arrives after a newer room update. Which Lobby state should the screen show?

Predict whether the client should trust the socket payload, accept whichever HTTP response finishes last, or keep the newer authoritative refresh. Then identify who may start a full, Ready room.

Check your prediction

Socket payloads are refresh hints, not replacement room state. LobbySession's request-version guard means stale responses are discarded; the most recently started request that is still current supplies the view. Separately, only the room host may start; the server checks membership, full sides, and every player's Ready state.

Now trace the boundaries

Recover a current room, then follow its invitation to a Match

This release exposes invitation-code rooms. The client reconciles its display from the authoritative active-state endpoint; Lobby events and ordinary mutation responses prompt a refresh.

  1. 01

    Open the Lobby and recover the active state

    LobbySession.start() opens the socket and requests /lobby/active. A room, Match-found, queue, or reconnect event starts another authoritative refresh. The socket payload itself does not replace the displayed snapshot.

    Create a private room or join by invitation code

  3. 03

    Refresh after changes and rejoin the room channel

    Socket payloads are refresh hints. Room mutations such as Create, Join, Ready, and Leave trigger a new getActive(); the request-version guard discards older responses. After connecting or joining a room channel, the session refreshes again to cover updates that happened during recovery.

  4. 04

    The host requests a start; the server checks the room again

    The button only enables when the host sees every slot filled and every player Ready. The server repeats the membership, host, capacity, side, and Ready checks before creating a Match. A successful start response carries its Match ID; duplicate lobby.matchFound events prompt refresh and do not cause a second handoff. The Match begins at MATCH_FOUND; the first Round has not started yet.
