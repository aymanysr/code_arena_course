Find your starting point

First, find where your teammate's repo keeps rules and tests. The paths below are examples from this repo, not rules for every project.

One small game story

A Match has players and Rounds. Each Round gives players a Problem. Run checks visible examples without changing the score. A Submission asks the Game to check hidden tests. The Game decides whether Submit is allowed; a Judge runs the code. Reveal shows the score after evaluation.

Lesson 1 follows a Submission to the Judge. Before you build it, you need a Match, an active Round, an allowed player, a Problem, and a clock. Read the lesson now if you want; build those parts first so its test has a real starting point.

Find six homes in your teammate's repo

  1. Find the folder that owns game rules and one rule test.
  2. Find the Problem data and tests for visible examples.
  3. Find one backend route and its test.
  4. Find the frontend Arena screen and a browser test.
  5. Find Match storage and its database test.
  6. Find the commands to run one test, lint, and the app.

Write those paths and commands in the repo's existing project notes. If the layout is similar to this one, look for rules in packages/arena-game/src/, tests in packages/arena-game/test/, routes in services/game/src/game/, and the screen in frontend/src/.

Use the owner that already exists. Create a new folder only when no current folder fits the job. The step cards on Course Home name a possible file and pattern for each part.

Your first coding action

After you find the paths, write a failing test for a Match with one active Round and a fixed clock. Check that an allowed player action succeeds and an action in the wrong phase is rejected. Then implement only enough rule code to pass that test.

Use the reference source and test links to understand behavior. Do not copy their code. Write your own implementation and make an equivalent test pass in your teammate's repo.
