What resets each Round—and what decides the Match?

In about 10 minutes: Follow how one Round score is counted, what resets when advancing, and how all Round scores and tie-breaks determine the final Match result.

Now follow the state

A fresh Round, one continuing Match

The Match keeps its history. Advancing clears the next Round's work area; it does not erase completed Round scores or restart the Match clock.

  1. 01

    Each side has one current counted result per Round

    A successful competitive Submit updates that side's counted score for this Round. A newer successful score replaces the old one: 100 followed by 40 leaves 40. If the newer Judge run fails as infrastructure, the last counted score stays 70; a failed run is not a zero.

  2. 02

    The hidden groups produce one Round score

    Each hidden-test group has a weight. The engine awards basis points for the passing fraction in each group, sums them, then rounds once to a whole percentage. With 70% weight at 3/4 passed and 30% weight at 2/3 passed: 5,250 + 2,000 = 7,250 basis points, which becomes 73/100.

  3. 03

    Advancing resets the next Round, not the Match

    advance() moves to the next pre-created Round and clears that Round's counted score, attempts, visible Run results, Reveal, and close/cutoff bookkeeping. Earlier Round records remain available for the final sum. The Match-wide start time stays the same, so the clock continues.

    Advance and reset Round state · round-lifecycle.ts:151 Match holds all Round records · records.ts:70 Reset behavior test · round-lifecycle.test.ts:72 Three Rounds; clock never resets · lifecycle-1v1.test.ts:14
  4. 04

    After the last Round, total first; tie-break only if needed

    The Match score is the sum of its Round scores (up to 300 in the three-Round setup). If totals tie, compare the sum of the times when each side achieved its final counted score across Rounds; lower wins. If those times also tie, fewer counted submissions wins. If both still tie, the result is a draw.

What these tests prove—and their limit

The scoring tests build concrete 1v1 examples for each comparison step. They show those cases follow the current rules; they are not a proof that every possible Match history has been tested. The pure compareSides() function is the shared rule used by final scoring.

When the Match deadline arrives

The final score comes from saved Round records

The deadline path persists the current Round Reveal, then saves the Match in MATCH_COMPLETE. The final result is computed from the saved counted Round records: each played Round contributes its counted score, unplayed Rounds contribute zero, and the existing score and tie-break rules still apply.

The server is already finished

The client does not need to advance the Round or ask the server to end the Match. The terminal Match state and current Reveal are available from the saved snapshot after reconnect.

The UI stages their presentation

For a deadline-completed Match, the screen first shows the saved current-Round Reveal and a See final result action. That action changes the presentation only; the server has already committed MATCH_COMPLETE. The ordinary completed flow can show the final result directly after its Reveal phase.
