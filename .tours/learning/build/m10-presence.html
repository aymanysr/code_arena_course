see / Two tabs still mean one online player

What happens after only one tab closes?

A Map looks up each player/Match pair. Its Set holds connection ids. Set size changes from zero to one on the first open and one to zero on the last close. In 2v2 the service tracks each member; in 1v1 it may aggregate a side.

Map
A lookup table from a key, such as a player, to a value.
Set
A collection that keeps each socket id only once.
Presence
Whether a player has at least one live connection.
Player status
The game state, such as coding or submitted.

understand / Name the boundary before coding

Why is one boolean per player not enough?

A boolean cannot tell whether one tab closed while another remains. Map<string, Set<string>> stores each socket id once per player/Match. Only an empty Set means offline. Keep this separate from Match status, such as coding or submitted.

Socket id
A unique identifier for one live browser connection.

build / Connect socket events to first-open and last-close

Which Game calls run on connection and disconnection?

In src/server/match.gateway.ts, first let Game.snapshot() verify Match membership. Then record each socket open and close for that same player and Match. The Presence tracker marks online on the first open and offline only after the last socket disconnects. A dropped socket is not a deliberate leave.
