# Guided Course Learner Path

## Destination

Produce a decision-ready UX specification for `.tours/learning/` that lets a beginner follow one lesson from concept to Practice code and check without guessing what to do next, while making Reference code, hints, notes, and the Practice/Team boundary clear. The playable `frontend/` game remains out of scope.

## Notes

This is a planning map for course UX, not an implementation task. Use the terms in `CONTEXT.md`: Match, Round, Problem, Run, Submission, Reveal, Reference, Practice, and Team. Consult the course Mission, existing learning-platform UX research, and the read-only browser review. Preserve the exact-source and evidence boundaries; do not treat a lesson status as proof of a rebuilt game.

## Decisions so far

None.

## Not yet specified

- The smallest learner walkthrough and the evidence that proves the redesigned route is understandable.
- The final information architecture after the primary learner route is chosen.
- Whether the first pilot should cover one lesson only or a complete M00–M01 study session.

## Out of scope

- Changes to the playable `frontend/` game.
- Rewriting the 68 lessons wholesale.
- A new framework, login, cloud sync, LMS, AI tutor, or mastery-scoring system.
- Course maintenance tooling except where it directly affects the learner path.
